# M10 — MoE naming and ownership

Status: **done**. Branch `m10-names`, merged after the gates below.
Parent: [m9b.md](m9b.md).

## Naming

- `Layers` → `CachedMoe`, and `layers.rs` → `cached_moe.rs`. The type is the
  model-wide index of `CachedLayer`s (plus the staging rings and prefill loan),
  so the name now says what it owns.
- `CachedLayer::registry` / `registry()` → `cached_moe` / `cached_moe()`.
- `provider_gpu.rs` → `gpu.rs`; `provider_cpu.rs` + `cpu_experts.rs` →
  `cpu.rs`. The CPU file owns both `CpuMoeProvider` and `CpuExperts`; they are
  two halves of the same CPU-only path.
- `decode.rs` and the former `components/` move under `src/moe/`. The decode
  path is MoE execution, and keeping it inside `moe` avoids a `moe` ↔
  `components` module cycle.

## Decode stages

`components/` is now `moe/stages/`. Each file owns one standalone struct with a
single `submit` entry point:

| stage | struct | entry |
|---|---|---|
| `route.rs` | `Route` | `Route::submit` |
| `preload.rs` | `Preload` | `Preload::submit` |
| `dma_miss.rs` | `DmaMiss` | `DmaMiss::submit` |
| `cpu_miss.rs` | `CpuMiss` | `CpuMiss::submit` |
| `gpu.rs` | `Gpu` | `Gpu::submit` |

The name is **stage**, not `task`: these are ordered pipeline stages carrying
`RoutePlan`, not independent queued jobs. `task` is already the executor's
closure type (`executor::Task`); `Stage`/`submit` leaves that vocabulary intact.
If the project later prefers `task`, rename `executor::Task` to `Job` first and
then rename the module and structs mechanically.
