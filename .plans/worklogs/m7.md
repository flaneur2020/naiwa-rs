# M7 — memory throughput

> The per-token cost work (round budget, depth sweep, waits, CPU-payload analysis) is in
> [`m7-per-token.md`](m7-per-token.md). This file is about **bytes**: what moves, how fast each link runs,
> what is actually the limit, and the order in which to attack it.

## The three links, measured

| link | measured | ceiling | used |
|---|---|---|---|
| **host DRAM, pure read** (`harness/m7/pack_layout.c`, 6 threads) | **28.6 GB/s** | ~35-40 GB/s | ~75% (that is the practical ceiling) |
| **host DRAM as the CPU experts see it** (fused Q4_K dots, 8 threads) | **8.2 GB/s** | 28.6 GB/s | **29%** |
| the same dots, **one thread** | 2.5 GB/s per core | - | instruction-bound, not bandwidth-bound |
| **PCIe** (gen4 x16), while the copy stream is busy | **12.8 GB/s** | ~25 GB/s | ~50% |
| PCIe, averaged over a round (53% duty cycle) | 6.4 GB/s | ~25 GB/s | 26% |
| **VRAM** | ~500 GB/s | - | ~0 - nothing is computed there that could be |

## What moves in one round (np8, counting prompt, `frac 0.2`, cache 4)

| item | experts/round | bytes | share of host reads |
|---|---|---|---|
| CPU misses (host DRAM read) | 353 | 745 MB | 28% |
| staged experts (host DRAM read + PCIe write) | 473 | 1000 MB | 37% |
| **preload / prediction copies (PCIe)** | 443 | **935 MB** | 35% |
| **total** | 1269 | **2.68 GB per round** | 100% |

Over a 185 ms round that is **14.5 GB/s of host DRAM traffic** - i.e. 51% of the 28.6 GB/s the machine can
actually sustain. So at np8 we are **half way to the DRAM ceiling**, and the ceiling arrives at about
np15 (measured: 18.5 GB/s of demand, and np15 is where the depth sweep turns over).

## The four levers, ranked

### 1. Stop paying for the preload (935 MB/round, 35% of all traffic)

`--lookahead-swaps` exists now (`0..N`, default 2) and the prediction replaces residents ~5x more often than it
fills empty slots. Measured at np8 (counting prompt, `frac 0.2`, cache 4, gen 96):

| swaps | hit rate | swaps over residents | round p50 | tok/s | CPU us/job | staged MiB / 4 rounds |
|---|---|---|---|---|---|---|
| 1 | 83.8% | 3817 | **165.5 ms** | **39.6** | 316.6 | 963 |
| 2 | 86.8% | 5968 | 185.8 ms | 38.1 | 350.1 | 935 |
| 3 | 88.2% | 5690 | ~180 ms | 43.2 | 321.3 | 887 |

So `1` gives the shortest round (**-11%** against the default 2) at a 3-point hit-rate cost, and the gain is
**not** from PCIe bytes (963 vs 935 MiB - the same) but from the CPU leg (317 vs 350 us/job) and from removing
stalls: every `replace` has to wait for the slot's readers (`wait_for_readers`) before overwriting it, so fewer
swaps is fewer stalls on the lookahead and fill paths, not less traffic. `3` buys hit rate back without paying
much, and the tok/s column is noisy because tokens/round varies run to run.

Recommendation: default `1` for deep drafting, `2` for shallow (that is what the np2 sweep preferred by a
narrower margin).

### 2. Move reads to VRAM: stage more, on a second stream

PCIe is at 26% average / 50% peak while VRAM sits idle, so the machine has link headroom that the current
schedule cannot use: the staged segment is queued **after** the residents on one stream, so raising `frac`
(measured 0.4, 0.6) lengthens the round. Put the staged segment on its **own stream** (the two segments are
independent - residents read bank slots, staged read the ring) and `frac` can rise, shifting read bytes from
host DRAM (29% used) to VRAM (unused).

### 3. Make the dots faster per byte (the CPU side's real limit)

Per core the Q4_K dot sustains 2.5 GB/s against 11 GB/s for a plain read at the same thread count, so it is
**instruction-bound**; the aggregate saturates at 8.2 GB/s with 8 threads and does not improve at 10 (SMT
siblings add nothing - the default is now capped at 8). The remaining kernel work is the per-super-block scale
and min decode, plus sharing the row's Q8_K quantisation across the layer's experts.

### 4. Do not chase the rest

Ruled out with measurements: interleaving the stacks (1.00x either way), warming predicted experts into L3
(slower - the concurrent PCIe streams evict them), huge pages (already 2 MB), pinning (already page-locked),
`RUN_ROWS` (64 is optimal: 32 -> 1641 us, 64 -> 1354, 128 -> 1467), and lower-bit CPU copies (breaks the
byte-exact oracle).

## Protocol

- **Traffic**: `NAIWA_ROUND_STATS=1` prints hit% / staged% / cpu% / staged_MiB / cpu_ms every 4 rounds.
- **PCIe**: `nsys` memcpy activity (`count`, `bytes`, busy time) in a steady-state window.
- **CPU**: `NAIWA_RET_DBG` (`compute_us` per job) and `NAIWA_FUSED_DBG` (us/pair).
- **Ceiling**: `harness/m7/pack_layout.c` for a pure read; always compare a change against that, not against
  the theoretical peak.
- Whole-run claims need >= 3 runs, liveness claims >= 6, and `frac 0` + `NO_LOOKAHEAD` stays byte-exact.
