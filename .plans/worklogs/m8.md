# M8 — cut the host launch chain

## Why this is the milestone

M7 ended with a decisive measurement: with `NAIWA_GPU_ONLY_EXPERTS` (a lossy probe that drops every
non-resident expert instead of staging or computing it, i.e. a perfect cache) the round improves by only
**+8%** (47.4 vs 43.9 tok/s at np8). So the entire miss path - CPU gemvs, their waits, the DMA, the preload -
is worth under a tenth of a round. What is left is the other 92%:

```
np8 round (~185 ms, 8 tokens)
  GPU compute (segments, attention, PLE)   40 ms   22%
  host launch chain + sampler             ~70 ms   38%   <- this milestone
  waits (CPU payload + staging)            74 ms   40%   <- mostly a consequence of the launch chain
```

The host terms are one thing: the token thread issues 30-40 CUDA calls per layer outside the captured MoE
segment (attention, PLE, router, gates, small elementwise ops), every layer, 48 layers per pass. At ~6 us per
`cuLaunchKernel` that is 0.2-0.24 ms/layer of pure submission, and because `STEP_DBG busy_ms/layer = 0.000` it
is **serialised against the GPU**: the GPU always finishes first and then waits.

## Target

| | now | after M8 |
|---|---|---|
| calls per layer (outside segments) | 30-40 | **1-2** |
| host launch chain | ~70 ms/round | **~10 ms/round** |
| np8 round | 185 ms | **~125 ms** |
| np8 per token | 23.1 ms (43 tok/s) | **~15.6 ms (64 tok/s)** |

(The target assumes the waits shrink with the chain, which they should: less host lateness means fewer exposed
gates.)

## M8.1 - capture the attention region per layer

`m6-graph.md` already did the groundwork: the per-layer resident inputs exist (`cos_sin` Vars, every paged
metadata map substituted per forward, `(row, id, weight)` lists from `dispatch_topk`, and a `RegionEntry` that
captures and replays with a `Var` input). What is missing is the **mixer window**: `attn_hc.mix`, `attn_hc.inject`
and `Mixer::Attention::forward`.

The one measured blocker: a naive capture of that window hangs (documented in `m6-graph.md`) because the paged
attention path reads tensors rebuilt per step. The fix is the metadata substitution, which is now written and
tested (`attn_capture::refresh`); the mixer window needs it wired the same way the mix/inject pair already is.

Gates: `frac 0` + `NO_LOOKAHEAD` byte-exact; `cuGraphLaunch` per step up by 48 and the launch count down by
~30/layer; round p50 down.

## M8.2 - fold the remaining single-node gates into the segment

The preload and staging gates are one-node graph launches replayed per layer. They are cheap per call (12-15 us)
but there are two of them per layer. Options, in order of preference:

1. move the `wait_ready` node **inside** the captured segment graph (captures are per layer, so the per-layer
   `sync_id` can be baked at capture time - no node-parameter update needed);
2. or replay them as plain kernels instead of graphs (already measured cheaper per launch: 5-6 us vs 12-15 us).

Gate: same launch-count reduction, `frac 0` byte-exact, staging wait p50 unchanged.

## M8.3 - capture the MTP head's block

The drafter runs one extra block per round (measured 1.9-3.2 ms, ~2-3% of the round) through the ordinary
layer path, so it inherits the same host launch cost. Once M8.1 works on decoder layers, the MTP site's block is
the same shape (its experts stay host-resident, so it needs the same treatment as a cached layer).

## M8.4 - re-measure at a real context

**Every number in M6/M7 was measured at `--depth 4`** (bench's `--depth` is the *decode context length*; the
`--prompt-len` case only feeds TTFT). At 4 tokens attention is trivial, so those numbers are MoE-dominated.
Before claiming anything about real serving, re-run the best configuration at `--depth 2048` and `4096`:
attention work enters the round, `frac`/cache choices may shift, and the host chain may matter less (or more).

Gate: the same three numbers (round p50, tokens/round, hit rate) at both depths, recorded side by side.

## Rules (unchanged)

- one fixed configuration per decision, recorded by commit; env switches only as read-only probes;
- `frac 0` + `NO_LOOKAHEAD` byte-exact after **every** change; `frac 0.55` against the two-variant set;
- >= 3 runs for a claim, >= 6 for a liveness claim;
- report round p50 and tokens/round (and hit rate) - not tok/s alone, and never a mean where a median exists;
- capture the attention region only if the region is free of host syncs and allocations: the audit already
  confirmed the **decode (paged)** path has neither.
