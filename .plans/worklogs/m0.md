## What M0 had to prove

The v2 architecture rests on two properties (architecture-v2 §3.1):

- **(A) host → GPU visibility** of the zero-argument `wait_ge_ptr` / `wait_copy_ptr`:
  `target` and `slot_off` are *mapped values, not kernel arguments*; the kernel spins
  until `*seq >= *target`, fences, then copies the mapped payload slot into device memory.
- **(B) graph replay**: the *same* kernel captured into one CUDA graph, replayed while the
  host rewrites payload / target / slot_off in mapped memory between replays. Nothing may be
  baked at capture time.

## Method and the design choices that mattered

- **Ring depth 8** (the doc invariant, ≥ 2): the host may write slot `k+1` while the GPU reads slot `k`.
- **`armed` handshake.** First version had the host publish immediately after launch; the
  launch latency meant the kernel *never actually spun* (`waited 0/20`) — the test silently
  measured nothing while still printing "correct". Fixed: the kernel raises a mapped `armed`
  flag as its first action and the host waits for it before publishing. Now the kernel is
  provably inside the spin loop at publish time.
- **`waited` counter.** A structural proof that the kernel honoured the *live* target
  (see finding 2 — this is what actually catches arg baking).
- **Four fence arms** (`-DM0_NO_HOST_FENCE`, `-DM0_NO_DEVICE_FENCE`, both) as controls, plus a
  **`-DM0_BAKE_TARGET` negative control** that bakes `target = 0` at compile time.

## Findings

1. **On Ada the fences are not load-bearing for this pattern.** All four fence arms pass,
   including both fences removed. The host "release fence" is also only a compiler barrier on
   x86. We keep both fences anyway — they cost nothing here and are the portable form strata
   documents (RDNA4 needs them). This is recorded as *measured on this card*, not as a licence
   to drop them.
2. **Correct values are not evidence of no arg baking.** In `m0_bakedtarget` the *values* were
   still 1000/1000 and 200/200 correct: the host is fast enough that the kernel, proceeding
   without waiting, read the already-updated `slot_off`. Only `waited == 0` exposed the bug.
   → Graph tests must carry a **structural** criterion; comparing outputs alone is insufficient.
   This directly justifies the roadmap's "structural criteria" principle.
3. **Replay works with per-iteration values from mapped memory.** The captured graph replayed
   200 times with a *different* target/payload every time, all correct — the core property
   the whole v2 design depends on.
4. **Time is dominated by the stream round-trip, not the spin** (~30 µs/iter and ~30 µs/replay);
   the harness syncs per iteration to compare. Not a performance measurement.
5. **A test that cannot fail proves nothing.** The `bakedtarget` control is what makes the PASS
   meaningful; it is kept in `run.sh` as a must-fail arm.

## Verdict / hand-off

- Both M0 criteria met: 1000/1000 visible, 200/200 replays correct, and the kernel demonstrably
  waited in every case; the baking control fails as required.
- **M0 is no longer a blocker.** `wait_ge_ptr` / `wait_copy_ptr` may use the zero-argument form;
  one captured graph is replayable indefinitely with per-iteration values in mapped memory.
- Next: these primitives move into the fork as **F3** (`mistralrs-core/src/cuda/doorbell.cu` +
  `doorbell.rs`), then M1 (static layout + descriptor-driven kernel).
- **Limitation**: single GPU, idle apart from the harness; no PCIe traffic, no competing streams.
  Contention is M4's problem, not M0's.
