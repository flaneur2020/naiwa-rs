# M9 — cleanup, simplification, ablation

## Why

M6-M8 tested a lot of mechanisms and several of them turned out to be **worth nothing or worse**. The code still
carries all of them, plus the probes that found that out. The engine is 9.6k lines with `expert_cache.rs` alone at
3.3k and **38 `NAIWA_*` env mentions**; eleven of those switches exist only because of decisions that have since
been measured. Every one of them is a place where the *shipped* configuration is ambiguous.

The rule this milestone enforces is the project's own: **one fixed configuration per decision, recorded by commit**
(`architecture-v2.md` §6.4). A switch that is still in the tree is a decision that has not been made.

## The ablation table (measured, this is the agenda)

| mechanism | flag | measured effect | verdict |
|---|---|---|---|
| **S2: residents launch before the staging gate** | `NAIWA_STAGE_SPLIT` | **78.9 -> 62.8 ms** per pass (-20%) | **keep, make it unconditional** |
| predictive preload / lookahead | (`NO_LOOKAHEAD` to disable) | hit rate 85% -> 20%, -25% throughput | keep, unconditional |
| `--lookahead-swaps 1` at deep draft | `--lookahead-swaps` | -11% round at np8 (165 vs 186 ms) | keep as a *flag* (it is a real tradeoff) |
| per-layer MoE segment graphs | `NAIWA_NO_CAPTURE` | **neutral** (44.1 vs 43.5 tok/s) | **delete** (with the capture machinery) |
| attention region capture (M8.1) | `NAIWA_ATTN_REGION` | **neutral** (43.9 vs 43.0) | **delete** (`attn_capture.rs`, ~400 lines) |
| dispatch-on-device flip (M6 P2) | `NAIWA_DISPATCH_USE` | **neutral** (77.4 vs 78.0 ms) | **delete** (`dispatch_topk` kernel + `DispatchBuf`) |
| L3 warming of CPU experts | `NAIWA_CPU_PREFETCH` | **-7%** | **delete** |
| staging ring size | `NAIWA_SCRATCH_SLOTS` | neutral 16 vs 64 | keep 16, drop the knob |
| expert cache size | `--expert-cache-gb` | 4 GB *slower* than 2 GB | keep 2 GB default, keep the flag |
| one-node gate graphs | (deleted in M6) | -140 lines, +0 perf | done |

### M9.1 - make the winners unconditional, delete the losers

1. `NAIWA_STAGE_SPLIT` -> always on; delete the flag and the non-split branch of `decode_forward`.
2. `NAIWA_NO_LOOKAHEAD` stays (it is the oracle's determinism knob) but the *default* path is the only shipping
   path; document it as a test-only probe in one place.
3. Delete `NAIWA_ATTN_REGION` and `src/vision_models/qwen4_exp/attn_capture.rs`, restoring the eager mixer. Verify
   with `frac 0` byte-exact and one np8 run within 2% of 43.5 tok/s.
4. Delete the per-layer segment capture: `MoeDecodeCapture` usage, `Bank::create_capture`,
   `CachedLayer::warmup_captures`, `fused_decode_capture`, `waitadd_replay` and the capture counters. Verify the
   same way (this is the biggest deletion, ~600 lines across the fork and the engine).
5. Delete `NAIWA_CPU_PREFETCH`, `NAIWA_DISPATCH_USE` + `dispatch_topk` + `DispatchBuf`, `NAIWA_SCRATCH_SLOTS`.
6. Delete the W-era probes that no longer answer anything (`NAIWA_MOE_DBG`, `NAIWA_PLE_DBG`, `NAIWA_MTP_DBG`'s
   prefetch counter, `NAIWA_LH_MODE` which the code already calls obsolete).

Acceptance for M9.1: `cargo test` green, `frac 0` + `NO_LOOKAHEAD` byte-exact against the frozen oracle, np8
round p50 within 2% of today's 170 ms, and **fewer than 12 `NAIWA_*` mentions** left (from 38).

### M9.2 - collapse the two sync protocols if only one is used

There are two CPU-return paths: the captured/schedule one (`ModelForward`-side `wait_add`, `ScheduleBuf`) and the
legacy per-layer `Channel`. The MTP site still uses the legacy one; the decoder uses the schedule one. Decide which
is canonical:
- if the MTP site can be moved to the schedule (it already publishes on `ScheduleBuf`), delete `Channel`
  (~200 lines) and the `NAIWA_*_CHANNEL` fallbacks;
- if not, document *why* in one comment at each entry point.

### M9.3 - one measurement harness, not eleven

Keep three probes and delete the rest: `NAIWA_STEP_DBG` (round + per-layer dry/busy), `NAIWA_ROUND_STATS` (the three
producers per pass) and `NAIWA_RET_DBG` (job latency). Everything else is either derivable from those three or was
a one-off. Put them in one `probes.rs` with one env prefix and one doc comment each.

### M9.4 - the model-level cleanup the fork is owed

`fork-inventory.md` lists ~150 lines of W-era probes in the fork (`PLE_DBG`, `MOE_DBG`, `MTP_DBG`, the resident
table machinery that the PLE decision made dead) - the PLE one is a documented cut point
(`worklogs/m6-graph.md`: the table lives on the CPU only, so `ResidentTable`, `copy_iq4nl`, `quantize_shards`,
`resident_bytes`, `planned_resident_table_bytes` are all dead, ~300 lines).

## Ablation protocol (this is the point of the milestone)

For every deletion, the number must be recorded *before* and *after*, with the flag doing the before:

```
NAIWA_STEP_DBG=1 <flag>=0  -> round p50 baseline
NAIWA_STEP_DBG=1 <flag>=1  -> round p50 with the mechanism
```

A mechanism whose two numbers are within run-to-run noise (5%) is deleted, and the pair of numbers goes into the
table above. A mechanism that pays is made unconditional and its flag removed. "Keep the flag in case" is not an
acceptable outcome - it is exactly the ambiguity this milestone exists to remove.

Gates for every commit: `frac 0` + `NO_LOOKAHEAD` byte-exact; `cargo test` green; np8 round p50 recorded.
